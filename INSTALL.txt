SHEPHERD - INSTALL INSTRUCTIONS (authoritative)
================================================

These are the authoritative, plain-text instructions for installing the
Shepherd OpenCode agent bundle into a user's global OpenCode config. Follow
them exactly. You are an AI agent performing the install on the user's behalf.

Shepherd is an OpenCode-only global agent bundle. It adds one primary agent
(`shepherd`) and seven `sheep-*` subagents (eight agents total) to the GLOBAL
OpenCode config. It does NOT modify project-local configs, and it must NEVER
overwrite the user's existing opencode.json as a whole.

Shepherd supports Windows, macOS, and Linux, provided Node.js and OpenCode are
available. The canonical install is the dependency-free installer:

    node tools/install.js

This file is part of the Shepherd repository/bundle. The installer resolves its
source bundle relative to the repository, so it must be run from a clone or
fetched bundle — it cannot run from this INSTALL.txt alone.


1. LOCATE THE BUNDLE
--------------------
Find the Shepherd repository on disk. It is the directory that contains this
INSTALL.txt, a `.config/opencode/` folder (the source bundle), and the
`tools/` directory (including `tools/install.js`).

- If you have the repository locally, use that path as <REPO>.
- Run the installer from within <REPO> (or pass an explicit target config
  root; see step 2).


2. CHOOSE THE TARGET CONFIG ROOT
--------------------------------
The installer writes to a global OpenCode config root resolved in this order:

  1. `--config-dir <path>` if passed (overrides everything).
  2. The `OPENCODE_CONFIG_DIR` environment variable, if set.
  3. Otherwise the default: `~/.config/opencode`
     (e.g. `$HOME/.config/opencode` on Linux/macOS,
      `%USERPROFILE%\.config\opencode` on Windows).

You normally need no flag: the default is correct when OpenCode stores config
in `~/.config/opencode`.


3. DRY RUN FIRST (RECOMMENDED)
------------------------------
Always preview before writing:

    node tools/install.js --dry-run

This reports the resolved config root, the 11 owned files and their status
(new / replace / unchanged), the opencode.json merge plan, and any conflicts —
with ZERO writes. Review the output. If it reports conflicts, see step 6.


4. REAL RUN
-----------
When the dry run looks correct, perform the real install:

    node tools/install.js

The installer:
  - Copies the EXACT 11 owned files into the matching structure under the config
    root, preserving any unrelated agents, commands, or plugins already present.
    The exact owned files (relative to the config root) are:
      agents/shepherd.md
      agents/sheep-cheap.md
      agents/sheep-fast.md
      agents/sheep-ui.md
      agents/sheep-test.md
      agents/sheep-search.md
      agents/sheep-review.md
      agents/sheep-docs.md
      command/sheeps-models.md
      command/herd.md
      plugin/shepherd.ts
    (8 agent markdown, 2 command markdown, 1 plugin TypeScript.)
  - Merges opencode.json (never overwrites): sets `default_agent` to
    "shepherd", replaces the eight Shepherd `agent` entries from the bundle,
    and appends/dedupes `"./plugin/shepherd.ts"` to `plugin`. All other
    top-level keys and unrelated agents are preserved exactly.
  - Validates types before any write (target/agent roots must be objects; each
    of the eight source agent values must be an object; `plugin` must be a
    string or an all-string array). On any validation failure it stops and
    writes nothing.
  - Creates sibling backups (`<file>.shepherd-backup-<timestamp>`) for any
    existing owned file it will replace, and for opencode.json if it will
    change.
  - Writes a machine-readable `shepherd-baseline-<timestamp>.json` recording
    the pre-install state (per-file existence, prior agent values, prior
    `default_agent` and `plugin` presence/shape, and backup paths) so the
    install is reversibly uninstallable. The baseline is written only when
    changes actually occur.
  - Performs ZERO writes on a no-op rerun: if every owned file is already
    identical and opencode.json is already merged, it writes nothing, creates
    no backups, and reports no changes.


5. VALIDATE
-----------
After a real run, the installer prints a summary (config root, file counts,
backups, baseline path). Optionally, from a clone, verify the model table:

    node tools/herd-models.js "<config root>/opencode.json"
    (e.g. node tools/herd-models.js ~/.config/opencode/opencode.json)

    node tools/herd-models.js "<config root>/opencode.json" --check

`--check` invokes `opencode models` to validate configured model IDs. When no
provider is reachable it reports "skipped" (exit 0) — that is expected and NOT
a failure. Do not block the install on it.

Restart OpenCode for the new agents and plugin to load.


6. CONFLICTS AND --force
-----------------------
The installer detects conflicts: an owned file that DIFFERS from the bundled
file, or a Shepherd `agent` entry whose value DIFFERS from the bundle. On a
conflict it STOPS before any write and reports the conflicting items.

`--force` is EXPLICIT authorization to replace differing Shepherd-owned files
and agent entries after backups are taken. It is NOT recommended by default.
Only use it when the user has clearly authorized overwriting customized
Shepherd content. Never use it to bypass unrelated-config protection.

    node tools/install.js --force


7. REPORT CHANGES
-----------------
Tell the user, concisely:
  - The backup location(s) created.
  - The files copied and their status (new / replaced / unchanged).
  - That opencode.json was merged (not overwritten) and what changed
    (default_agent set to shepherd; eight Shepherd agent entries merged;
    plugin path appended/deduped).
  - The baseline file path (for reversible uninstall).
  - That model IDs are defaults and provider-dependent; they may need
    adjusting via `/sheeps-models` if the provider does not expose them.
  - That they must RESTART OpenCode for the new agents and plugin to load.


8. STOP AND ASK BEFORE
---------------------
Do NOT proceed if you encounter:
  - A situation that would require overwriting the whole opencode.json.
  - Conflicting or ambiguous instructions, missing context, or a public-contract
    decision you cannot make safely.
  - Operations beyond the scoped backup + merge described here (e.g. deleting
    unrelated config, force-resetting git, removing other agents).
  - A protected area edit (auth, billing, secrets, migrations, infrastructure,
    CI/CD, lockfiles, public APIs) not explicitly authorized by the user.
In any of these cases, STOP, explain the conflict, and ask the user before
doing anything further.


9. UNINSTALL
------------
There is no automated uninstaller. Uninstall is state-aware and reversible from
the `shepherd-baseline-*.json` written at install time (step 4). If the baseline
is missing or ambiguous, STOP — do not guess. Apply these guards: restore a
pre-existing changed file only after verifying its current content still matches
the installed bundle (if it differs — a post-install user edit — STOP and back it
up/retry only after asking, never overwrite blindly); leave pre-existing
unchanged files (no backup) untouched; delete a newly added file only if it
still matches installed content, otherwise STOP/ask. For opencode.json, restore
baseline values only after detecting no post-install changes; otherwise STOP and
merge manually from the baseline without deleting user changes. See README.md
"Safe uninstall" for the exact procedure.
